# 仓储成本与经营分析模型

[![tests](https://github.com/wangyihanworld-ux/Warehouse-analysis-model/actions/workflows/tests.yml/badge.svg)](https://github.com/wangyihanworld-ux/Warehouse-analysis-model/actions/workflows/tests.yml)

这是一个使用 Python 开发的仓储分析工具。模型读取期初库存、出入库流水和费率规则，按照 FIFO 重建批次流转，计算仓储费用、库存余额、存放天数与库龄，并输出面向财务和经营分析的 Excel 报告。

公开仓库只包含源码、合成测试和构建入口，不包含真实 ERP 数据、真实费率、客户名称、业务报告、运行数据库、日志、用户设置或 EXE 发布包。

演示基准结果：仓储费 20,101.90 元，期末库存 375 吨。自动化测试覆盖 FIFO 跨批次分摊、库存不足整笔拒绝、数量守恒、费率匹配、库龄、敏感性和报告生成。

## 项目解决的问题

仓储费用不仅受期末库存影响，还与批次入库时间、出库顺序、存放天数和适用费率有关。仅用期末库存乘以统一费率，无法准确还原不同批次的费用，也难以解释费用变化。

```text
期初库存与出入库流水
        ↓
字段识别和输入校验
        ↓
按仓库和物料建立FIFO队列
        ↓
出库批次拆分与费率匹配
        ↓
仓储费用、库存、存放天数和库龄计算
        ↓
经营汇总、敏感性分析与Excel报告
        ↓
数量守恒和异常记录
```

## 主要功能

- 按仓库和物料维护独立的 FIFO 队列；
- 支持期初库存以及一笔出库跨多个入库批次；
- 按物料、品类和仓库统一规则的优先级匹配费率；
- 计算已出库批次的周转天数和仍在库批次的库龄；
- 输出物料、品类、仓库和月末库存汇总；
- 分析库存量、存放天数和费率变化下的费用情景；
- 检查每个批次的数量守恒并记录库存不足等异常；
- 生成包含 12 张工作表的 Excel 业务报告；
- 提供桌面 GUI、历史记录、权限和多仓批量分析模块。

## 一键运行完全脱敏 Demo

建议使用 Python 3.12。首次运行先安装依赖：

```powershell
python -m pip install -r requirements.txt
```

无需准备业务文件，运行：

```powershell
python -m warehouse_analysis.demo
```

指定输出目录：

```powershell
python -m warehouse_analysis.demo --output-dir .\my_demo_output
```

命令会生成合成输入工作簿和完整分析报告。合成输入包含“演示说明”“出入库明细”“期初库存”和“计价规则”四张工作表。仓库、物料、批次、数量和费率均为人为构造，不对应任何真实客户、合同或业务记录。输出目录已被 Git 忽略。

## Demo关键结果

在报告的“批次明细”中筛选出库批次 `DEMO-OUT-001`，可以观察一笔 130 吨出库如何按 FIFO 拆分：

| 原始批次 | 批次来源 | 分摊数量 | 存放天数 | 仓储费 |
| --- | --- | ---: | ---: | ---: |
| DEMO-OPEN-001 | 期初库存 | 100 吨 | 57 天 | 3,306.00 元 |
| DEMO-IN-001 | 后续入库 | 30 吨 | 28 天 | 487.20 元 |

两个分摊数量合计 130 吨，与原始出库数量一致。完整演示包含 2 个仓库，期末库存合计 375 吨，计算仓储费合计 20,101.90 元，数量守恒异常为 0。

建议按“首页摘要、批次明细、仓库经营分析、月末库存快照、费用敏感性分析、数量守恒校验”的顺序查看报告。

## 关键业务口径

- FIFO顺序：期初库存和入库批次按日期排序；同一天的流水按原始数据行顺序处理。
- 库存不足：如果一笔出库大于当时可用库存，模型整笔不分摊，并记录原始出库量、可用量和缺口，避免部分分摊造成报告口径不一致。
- 存放天数：使用出库日期减入库日期；仍在库批次使用统计截止日期减入库日期，不默认加一天。
- 费率日期：已出库批次使用出库日有效费率，仍在库批次使用统计截止日有效费率；当前版本不按费率变更日期分段计费。
- 敏感性分析：属于其他因素不变的单因素线性模拟，不重新执行 FIFO，也不代表因果预测。排名反映预设情景区间内的费用影响，不代表因素的内在重要性。
- 数量守恒：每个入库批次均检查“原始入库量 = 累计出库量 + 剩余库存量”。

上述口径应在用于真实业务前与仓储合同、财务制度和源系统流水顺序核对。

## 项目结构

```text
warehouse_analysis/
├─ core/          FIFO、费率匹配、数据模型和核心计算
├─ io/            Excel和ERP输入适配、标准化与校验
├─ analysis/      经营汇总、费用归因和敏感性分析
├─ reporting/     Excel报告与文件命名
├─ ui/            tkinter桌面界面
├─ demo.py        完全脱敏的一键演示
└─ service.py     连接输入、计算、分析和报告的服务层

tests/            不依赖真实业务数据的自动化测试
packaging/        Windows构建入口和PyInstaller配置
config/           本地费率与配置说明
```

## 数据安全

- 不要提交真实ERP文件、客户名称、合同费率或业务报告；
- 不要提交运行数据库、日志、用户设置或管理员密码；
- 公开演示只使用 `warehouse_analysis/demo.py` 中固定的合成记录；
- 正式使用时应在本地通过环境变量配置管理员密码并维护脱敏费率配置。

## 当前局限

- 单因素敏感性采用线性假设，不重新运行FIFO；
- 费率变更使用关键日期上的有效费率，未做跨期间分段计费；
- 同日流水依赖源数据行顺序，源系统若能提供时间戳应优先使用时间戳；
- 公开版不包含真实业务测试夹具，因此不能展示生产环境准确率或节省工时。
